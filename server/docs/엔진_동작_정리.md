# ROADPOD 대화 엔진 동작 정리

> 서버(`backend/roadpod/`)가 실제로 어떻게 움직이는지 정리한 문서다. 코드 기준 2026-11-13.
> 기능 명세(「3. 앱 주요 기능 및 차량 특화 요소」)의 ①~⑦과 재생 제어가 어디서 어떻게 구현됐는지, 앱이 무엇을 보내고 받아야 하는지까지 담았다.
> **데모를 바로 보려면 13장**(`demo/run_demo.py`, 페르소나 정하은의 출근길 A·퇴근길 B).

## 1. 한눈에 보기

```text
 차량 앱 (Pleos Connect)                         서버 (FastAPI)
 ──────────────────────                         ─────────────────────────────────────────────
 POST /api/v1/sessions ───────────────────────▶ 세션 생성 (session_id, ws_path)
 WebSocket /ws/v1/sessions/{id}
   이벤트 ─▶  context.updated (1초 단위)  ─────▶ Director.process()
              session.started                    ├─ 주행 맥락 반응 (drive.py)      ② ⑥
              user.utterance / user.action       ├─ 에피소드 진행 (engine.py)       ① ③
              navigation.guidance_*              ├─ 사연 잡기·릴레이 (relay.py)     ④ ⑤
              command.ack                        ├─ 재생 제어 (내비 일시정지/재개)  ③번 Pain
              vehicle.parked / session.ended     └─ Q Diary (diary.py)             ⑦
   명령 ◀─  dj.speak / story.preview / story.incoming / media.pause / media.resume / diary.ready
 POST /api/v1/stories/{id}/approval ──────────▶ 승인 → 검수 → 다른 차로 릴레이
 휴대폰 QR ─▶ GET /diaries/{id} ──────────────▶ 그림일기 페이지
```

| 파일 | 역할 |
|---|---|
| `main.py` | REST·WebSocket 입구, 승인 API, Q Diary 페이지 |
| `engine.py` | `Director`: 세션 상태, 발화 순서, 에피소드 진행, 모든 이벤트 처리 |
| `topics.py` + `data/topics.json` | 주제 카탈로그 30개(5개 분야)와 청취자별 주제 선택 |
| `producer.py` | 에피소드 제작: 리서치 → 출처 검증 → 원고 작성 → 원고 검사 |
| `openings.py` | 방송 오프닝, 주제 훅, 대기 중 브리지 멘트 |

## 2. 핵심 규칙: 한 번에 한 마디

차는 TTS를 하나씩만 재생한다. 서버도 똑같이 **"지금 재생 중인 명령은 하나"**를 지킨다.

1. 서버가 `dj.speak`(또는 `story.incoming`)를 보내면 그 명령이 **재생 슬롯**을 차지한다.
2. 앱이 `command.ack`로 `COMPLETED / INTERRUPTED / FAILED`를 보내야 슬롯이 비고 다음 말이 나간다.
3. 슬롯이 차 있을 때 생긴 말은 **대기열(pending)**에 들어간다. 주행 코멘트·사연 답변처럼 급한 건 **맨 앞**에 끼운다(현재 문단이 끝나자마자).
4. ACK가 안 오면(패킷 유실, 앱 오류) `30초 + 글자수/3초` 뒤 포기하고 다음으로 넘어간다.
5. `INTERRUPTED`로 끊긴 문단은 기억했다가 "이어서 들려드릴게요."로 다시 들려준다.

### 문단과 문단 사이에서 일어나는 일 (우선순위 순)

`advance()`가 다음에 무엇을 말할지 정한다.

1. **대기열**(pending): 주행 코멘트, DJ 답변, 사연 초안 안내
2. **끊긴 문단 재생**
3. **받은 사연**(inbox): 다른 운전자가 보낸 사연, 내 사연에 온 답장, 릴레이 방송. *에피소드 오프닝(훅) 전에는 끼우지 않는다.*
4. **에피소드 다음 문단**. 단,
   - 남은 원고가 도착 전까지 못 끝날 분량이면 → **OUTRO로 건너뜀** (①)
   - 다음이 OUTRO면 그 직전에 **사연 슬롯** 한 번 (⑤)
5. 에피소드가 끝나면 → 곧 도착(ETA ≤ 3분)이면 **작별 인사**하고 멈춤, 아니면 **다음 주제** 자동 시작

## 3. 이야기(에피소드)는 어떻게 만드나 — 기능 ①③

### 3-1. 주제 고르기 (`topics.py`)

카탈로그: 30개 질문, 5개 분야(마음과 심리 / 관계와 소통 / 일과 성장 / 책과 문화 / 시사와 사회). 각 주제에 요약, 관점(angles), 출퇴근 적합도, 최소 길이(분), 민감도가 있다.

고르는 순서:
1. 최근 **14일 안에 들은 주제는 제외** (다 들었으면 반복 허용)
2. **ETA**가 있으면 남은 시간 안에 끝낼 수 있는 주제만 (`min_minutes ≤ 남은 분`)
3. 청취자가 고른 **관심 분야**(`set_interests`)가 있으면 그 안에서
4. 25% 확률로 **탐색**: 이번 출퇴근에서 가장 덜 들은 분야
5. 나머지 75%는 **취향 점수**: `출퇴근 적합도 + 0.6 × 분야 선호도` 상위 3개 중 가중 추첨

**출퇴근별 메모리(③)**: 분야 선호도는 *같은 출퇴근 유형의 기록만* 본다. 출근길에 건너뛴 분야가 퇴근길 추천에 영향을 주지 않는다.

| 청취 신호 | 점수 |
|---|---|
| 끝까지 들음 | +1 |
| 말을 걸었거나 사연을 남김 (가장 강한 신호) | +2 |
| 오프닝만 듣고 건너뜀 | −2 |
| 중간에 건너뜀 | −1 |

DJ 목소리 분위기도 출퇴근별로 다르다: **출근 BRIGHT / 퇴근 CALM / 그 외 WARM** (`dj.speak.voice_style`).

### 3-2. 에피소드 구성

```text
HOOK      오프닝 인사(첫 에피소드만) + 오늘의 질문      ← 템플릿, 즉시 방송
(BRIDGE)  본문이 아직 준비 중이면 주제 요약 한 마디     ← 템플릿
FRAME     질문을 여는 문단                              ┐
PERSPECTIVE × 3~     관점별로 깊이 들어가는 문단        ├ 리서치 + AI 원고
(사연 슬롯) 같은 주제·분야의 다른 운전자 사연 하나      │ ← 있을 때만
OUTRO     결론 없이 질문 하나로 닫기                    ┘
```

### 3-3. 본문 제작 파이프라인 (`producer.py`)

1. **리서처** (OpenAI + 웹검색 필수): 사실·통계·연구 3~8개, 서로 긴장하는 관점, 청취자 질문을 JSON으로
2. **출처 검증** (코드): 검색 도구가 *실제로 돌려준 URL*의 사실만 남김. 블로그·카페·나무위키·SNS 차단, 한 출처당 최대 3개, 시사 주제는 2년 이내 자료만. 하나도 안 남으면 "사실 없이 관점만" 모드
3. **작가**: 8~10문단, 2400~3000자. 사실을 말할 땐 매체와 연도를 말로 밝힘. 1500자 미만이면 한 번 다시 씀
4. **원고 검사** (코드): 출처 없는 숫자·"연구에 따르면" 문단 삭제, 괄호 출처·F1 같은 표기 제거, 구조 용어(HOOK/FRAME/…)가 들어간 문장 삭제, 문단당 450자로 자름
5. 실패하면 어떤 단계든 **카탈로그 원고**(사실 주장 없는 관점 소개)로 대체 — 방송이 끊기지 않게

**캐시**: 리서치는 주제별, 원고는 주제×출퇴근별로 DB에 저장해 모든 청취자가 공유한다. 시사 12시간, 그 외 30일 뒤 다시 만든다. `ROADPOD_DB`가 설정돼 있어 서버를 재시작해도 남는다.

**지연 대책**: 리서치+작성은 약 40초 걸린다. 훅과 브리지가 나가는 동안 만들고, **25초**(`BODY_WAIT_SECONDS`) 안에 안 끝나면 카탈로그 원고로 바로 이어 간다. 리서치는 뒤에서 계속 돌아 저장되므로 다음 청취자는 리서치된 버전을 듣는다. 다음 주제는 미리 골라 미리 만들어 둔다(건너뛰기·자동 넘김에 공백 없음).

미리 전부 만들어 두려면:

```bash
PYTHONPATH=backend .venv/bin/python -m roadpod.prewarm --all --commute UNKNOWN TO_WORK FROM_WORK
```

### 3-4. ETA에 맞춘 길이 조정 (①)

- 주제 선택 때 남은 시간 안에 끝낼 수 있는 주제를 고른다.
- 방송 중 **남은 원고(글자수 ÷ 5.5자/초) > ETA + 30초**가 되면 남은 관점을 건너뛰고 **OUTRO로** 간다.
- ETA가 **3분 아래로 내려가는 순간** 지금 주제를 마무리 모드로 바꾸고, 끝나면 "곧 도착이에요…" 작별 인사 후 새 주제를 시작하지 않는다.

### 3-5. 운전자가 말을 걸면

`user.utterance`(최종 인식만) → 주제·현재 문단·최근 대화·차량 상황을 넣어 AI DJ가 1~2문장으로 받아 주고 방송으로 돌아간다. 개인 질문을 캐묻지 않고, 운전 중 부담을 주지 않도록 프롬프트로 제한한다.

### 3-6. 말로 하는 조작 (운전 중에는 화면 대신 목소리)

| 하은이 말하면 | 서버 동작 |
|---|---|
| "큐큐야, 다른 거" / "넘겨" (짧은 말) | 미리 만들어 둔 다음 주제로 |
| "…사연으로 남겨 둘래. (내용)" | 그 뒤의 말을 사연으로 잡음 (앞의 군말은 버림) |
| "이 노래 드랍해줘" | 앱이 알려 준 지금 재생 곡(`now_playing`)을 음표로 |
| "응 / 보내" · "아니 / 보내지 마" | DJ가 "보낼까요?"라고 물은 직후에만 승인·거절로 처리 |

DJ가 무언가를 물으면(사연 보낼지, 오늘의 한 장면) **다음 문단으로 바로 넘어가지 않고 10초(`ANSWER_WAIT_SECONDS`) 기다린다.** 답이 없으면 사연은 주차 후 화면 승인으로 넘기고 방송을 이어 간다.

### 3-7. 책 한 권 코너 (퇴근길)

리서치가 질문과 관련된 **실제 책 한 권**을 검색으로 확인하면(출판사·서점·언론의 책 소개 페이지가 검색 결과에 있어야 함) 퇴근길 원고의 OUTRO 바로 앞에 `BOOK` 문단이 들어간다. 제목·저자를 밝히고 핵심 아이디어만 2~3문장으로 소개한다. **책 문장을 길게 읽지 않는다**(저작권). 확인된 책이 없으면 코너 자체가 없다.

### 3-8. 음악 코너 (C: 서버가 무료 음원을 편성) + 차에서 듣던 음악 (A)

- **C, 서버 편성**: 에피소드 본문을 3문단(`MUSIC_EVERY`) 들을 때마다 DJ가 "노래 한 곡 듣고 이어 갈게요. ○○." 하고 `music.play` 명령을 보낸다. 에피소드당 최대 2곡, OUTRO 바로 앞·도착 마무리 중·사연/질문 중에는 넣지 않는다.
- 곡은 `backend/roadpod/data/music.json`에서 출퇴근에 어울리는 곡(적합도 0.5 이상)만 고른다(출근 밝은 곡, 퇴근 차분한 곡). 같은 운행에서 반복하지 않는다.
- 음원 파일은 `backend/roadpod/data/music/`에 넣으면 `/music/<파일>`로 나간다. **라이선스가 허락하는 음원만**(Pixabay Content License, CC0, CC BY 등). 지금은 **샘플 슬롯 6개**(파일 없음)라 명령은 나가지만 소리는 없다.
- 서버가 튼 곡은 서버가 알고 있으니 "이 노래 드랍해줘"가 그 곡으로 바로 음표가 된다.
- **A, 차에서 듣던 음악**(멜론·라디오 등): 앱이 `user.action: now_playing`으로 곡 정보만 알려 준다. 서버는 그 곡을 틀거나 고르지 않는다(마이크 드롭용).
- 앱이 할 일: `music.play`의 `url`을 재생하고 끝나면 `COMPLETED` ACK, 내비 안내 중엔 멈춤(`media.pause`/`resume`과 동일).

## 4. 주행 맥락 — 기능 ②와 재생 제어(Pain ③)

### 4-1. 주행 코멘트 (`drive.py`)

`context.updated`가 올 때마다 **직전 상태와 비교**해서 *변한 순간*에만 반응한다(막힌 상태가 계속되면 다시 말하지 않음).

| 이벤트 | 조건 | 예시 멘트 |
|---|---|---|
| 정체 + 비 (같은 순간) | 둘 다 바뀜 | "올림픽대로가 비 때문에 조금 느려요. 도착은 10분쯤 늦어질 것 같아요. 그럼 아까 이야기 마저 이어 갈게요." |
| 정체 시작 | 교통 `JAM` (verified) 로 바뀜 | "길이 조금 막히기 시작하네요. 서두르지 않아도 괜찮아요…" |
| 정체 해소 | `JAM` → `FREE` | "막혔던 길이 풀리고 있어요. 속도가 붙을 때일수록…" |
| 비/눈 | 날씨 `RAIN/SNOW` (verified) 로 바뀜, 또는 와이퍼 꺼짐→켜짐 | "와이퍼가 움직이기 시작했네요. 빗길에서는…" |
| 곧 도착 | ETA가 3분 아래로 | (멘트 없음) 현재 주제 마무리 → 작별 인사 |

- **템플릿만 사용**: 즉시 나가고, 도로 사실을 지어내지 않으며, AI 호출로 WebSocket을 막지 않는다.
- 도로 이름은 내비가 보낸 `road_name`, 지연 분은 **처음 받은 ETA로 계산한 도착 예정 시각과 지금 ETA의 차이**(3분 이상일 때만).
- 날씨는 오프닝에서 말하지 않는다. 필요한 순간(비가 오기 시작할 때)에만.
- **퇴근길 회고 질문**: 정체로 멈춰 있고 내비 안내가 없을 때 한 번만 "오늘 하루에서 한 장면만 고른다면요?". 답은 일기에 쓰이고, 운전자가 개인 메모리에 동의했을 때만(`set_memory_consent`) 저장된다. 공유·릴레이하지 않는다.
- 현재 문단이 끝나자마자 끼우고, 그다음 에피소드가 하던 곳에서 이어진다.
- 같은 종류는 10~15분, 어떤 코멘트든 최소 90초 간격. 내비 안내 중·주차 중·사연 말하는 중에는 하지 않는다.
- `verified=false`인 교통·날씨는 무시한다.

### 4-2. 재생 제어

| 상황 | 서버 동작 |
|---|---|
| `navigation.guidance_started` | `media.pause`, 대기열의 지난 말 폐기, 이후 새 발화 보류 |
| `navigation.guidance_ended` | `media.resume`, 끊긴 문단부터 이어서 |
| 앱이 `INTERRUPTED` ACK | 그 문단을 기억했다가 "이어서 들려드릴게요." |
| 주차 확인(`parked_confirmed`) | 새 발화 없음 (Q Diary만) |
| 받은 사연이 내비 중에 도착 | 버리지 않고 보관했다가 다음 문단 사이에 |

방향지시등·주의 구간 판단은 **앱이 로컬에서** 한다(`AttentionEvaluator`, `CommandGate`). 계약에 방향지시등 필드가 없어서 서버는 내비 안내 신호로만 판단한다.

## 5. 사연은 어떻게 주고받나 — 기능 ④⑤

### 5-1. 흐름

```text
[A 운전자]                     [서버]                              [B 운전자]
사연 보내기 버튼 ───────▶ request_story: "편하게 말씀해 주세요"
"회의 때 알림이…" ──────▶ 후속 질문 1개 (AI)
"솔직히 지쳐요" ────────▶ 두 발화를 합쳐 익명 사연 초안 (AI)
                          → story.preview  (아직 비공개)
(주차 후) 공개 ─────────▶ POST /approval
                          → 검수: 개인정보·욕설·자해 표현
                          → PUBLISHED  (또는 BLOCKED)
                          → 매칭되는 차에 바로 전달 ──────────▶ story.incoming
                                                                "다른 운전자분이 보내 주신 사연이…"
                                                     ◀────────── 사연 보내기 (맞사연)
                          → 관계 분류: 공감/반론/후속
A의 다음 세션 오프닝 뒤 ◀── "지난번 보내 주신 사연에 답이 왔어요"
                          → 답 2개 이상 쌓이면 새 주제 후보
```

### 5-2. Story Catch (④)

- **시작**: `user.action: request_story`(버튼), 또는 `user.utterance`에 `intent: "CREATE_STORY"`(앱의 공유 모드).
- **이미 한 번에 다 말했으면(30자 이상) 후속 질문 없이** 바로 초안. 짧으면 **후속 질문 한 번**: 첫 발화 뒤 DJ가 감정이나 그때 생각을 하나만 묻는다("그 순간 가장 크게 든 마음은 뭐였어요? 편하실 때 한마디만…"). 답하면 합치고, "이대로 보내 줘" 같은 짧은 거절이면 첫 발화만, **45초 동안 말이 없으면** 그대로 초안을 만든다.
- **초안**: AI가 1인칭 2~4문장(120~220자) 익명 사연으로 정리. 이름·회사·지명·차량번호·연락처는 빼거나 흐린다("제 동료 김민수 대리" → "한 동료"). AI가 없으면 개인정보만 지운 원문.
- **함께 저장되는 맥락**: 그때의 주제·분야, 출퇴근, 교통, 날씨, 도로 구간. *사연 본문에는 넣지 않고* 매칭에만 쓴다.
- **개인정보가 들리면** 초안을 만들지 않고 다시 말해 달라고 한다(전화번호, 이메일, 주민번호, 차량번호).
- **멈춰 있을 때(신호 대기·정체)**: DJ가 공감 한마디 + 초안을 읽어 주고 "보낼까요?" → "응 보내"면 바로 검수·발행, 이어서 "큐큐~" 응원. 대답 전에 차가 출발하면 질문을 거두고 초안은 주차 후 화면 승인으로 넘긴다.
- **달리는 중**: 초안은 `story.preview`로만 가고, **명시적 승인 전에는 아무에게도 안 나간다.** 앱은 주차 후에 승인 창을 띄운다.

### 5-3. 승인과 검수

`POST /api/v1/stories/{story_id}/approval` `{session_id, approved}`

| 응답 status | 뜻 |
|---|---|
| `PUBLISHED` (`published: true`) | 검수 통과, 다른 운전자에게 전달 시작 |
| `BLOCKED` | 개인정보 또는 욕설·자해 표현 → 전달 안 함 |
| `REJECTED` | 운전자가 공개 안 함 선택 |
| 403 / 404 / 409 | 남의 사연 / 모르는 세션 / 이미 결정됨 |

### 5-4. Story Relay (⑤)

**누구에게 가나 (매칭 점수, 2점 이상이면 바로 전달)**

| 조건 | 점수 |
|---|---|
| 지금 같은 주제를 듣는 중 | +3 |
| 같은 분야 | +1 |
| 같은 출퇴근 유형 | +1 |
| 같은 교통 상황(정체 등) | +1 |
| 같은 도로 구간 | +1 |

**언제 들리나**
- **바로**: 승인 순간 매칭되는 차가 조용하면 즉시, 말하는 중이면 그 문단이 끝난 뒤.
- **나중에 (사연 코너)**: OUTRO 직전 슬롯에서 같은 주제 → 같은 분야 → 같은 출퇴근 유형 순으로 고른 사연 한 편. **답장이 달린 사연이면 사연과 답장을 이어서** "이 이야기와 딱 맞는 사연이 있어요… 여기에 다른 청취자님이 이렇게 답장을 보내셨어요… 사연과 답장이 오가니까 라디오가 조금 더 따뜻해지네요."
- 한 사람이 같은 사연을 두 번 듣지 않는다. 자기 사연은 자기에게 안 간다.

**맞사연**: 사연을 들은 직후(그 에피소드가 끝나기 전) 사연 보내기를 누르면 그 사연에 대한 답이 된다. 키워드로 관계를 나눈다.

| 관계 | 판단 단어 예 | DJ 소개 |
|---|---|---|
| COUNTERPOINT | 반대, 오히려, 글쎄 | "조금 다른 생각을 보내 주신 분이 있어요." |
| EMPATHY | 공감, 저도, 같은 마음 | "공감하는 답장이 왔어요." |
| FOLLOW_UP | 그 외 | "이어지는 이야기가 왔어요." |

원래 사연을 쓴 사람이 운전 중이면 바로, 아니면 **다음 세션 오프닝 직후** 들려준다. 퇴근길이면 "아침에 남겨 주신 사연에 답장이 왔어요. …", 두 번째부터는 "다른 분은 이렇게 보내 주셨어요. …"

**사연 → 새 콘텐츠**
- **릴레이 방송**: `user.action: play_relay` → 답이 가장 많이 달린 사연 스레드를 원 사연부터 답장까지 이어서 들려준다.
- **새 주제 (공통 토픽 풀)**: 발행된 사연마다 AI가 **원문이 아닌 고민만 뽑아** 열린 질문 하나를 만든다(예: "모든 사람과 꼭 좋은 관계를 유지해야 할까요?") → `topic_candidates`. 운영자가 `GET /api/v1/topic-candidates`로 보고 `POST /api/v1/topic-candidates/{id}/adopt`로 승인하면 **공통 토픽 풀에 들어가 누구의 다음 방송 오프닝으로도 쓰인다**(DB에 저장, 재시작해도 유지).

## 6. 마이크 드롭 — 기능 ⑥

- **남기기**: "큐큐야 이 구간에 「밤양갱」 노래 하나 남겨줘" 같은 말, 또는 `user.utterance`에 `intent: "DROP_MUSIC"`, 또는 `user.action: drop_music` + `track`. AI가 "곡 제목 - 가수"만 뽑는다(없으면 따옴표 안 글자 / 요청 단어를 뺀 나머지).
- **저장**: 곡, 도로 구간(`road_segment_id`), 도로 이름, 시간대(아침/낮/저녁/밤), 교통 상황.
- **전하기**: 다른 운전자가 **같은 도로 구간에 들어서는 순간**, 또는 **같은 시간대에 정체가 시작되는 순간** "이 구간을 지나던 다른 운전자가 음표 하나를 남겨 두었어요. 「…」"
- 한 사람에게 같은 음표는 한 번만, 10분에 한 번까지. **음악 재생 자체는 하지 않는다**(곡 소개만, 음원 권리 문제).

## 7. 오늘의 Q Diary — 기능 ⑦

1. 앱이 `context.updated`로 `parked_confirmed: true`를 보낸 뒤 `vehicle.parked`를 보내면(속도 0만으로는 안 됨) 세션당 한 번 만든다.
2. 재료: 이번 운행에서 들은 주제, 운전자가 한 말(최근 5개), **오늘 보낸 사연(아침 사연도 저녁 일기에)**, 돌아온 답장, 저녁 회고, 들은 사연, 남긴·받은 음표, 날씨, 교통.
   화면 구성: **오늘의 한 줄**(저녁 회고 → 내 사연의 질문 → 오늘의 주제 순), **큐큐's 코멘트**(AI 한 문장), 그림, 일기 글, 보낸 사연·돌아온 답장·회고 목록.
   주차가 확인되면 DJ가 마지막 한 마디를 한다: 출근 "큐큐~ 오늘 드라이브를 Q Diary로 만들어 봤어요! 오늘 출근도 파이팅입니다! 저녁에 만나요~", 퇴근 "… 푹 쉬어요. 고생 많으셨습니다."
3. **글**: AI가 운전자 시점 일기체 3~4문장(200자 이내). 기록에 없는 일은 쓰지 않고, 다른 사람 이름·회사·지명은 흐린다.
4. **대표 감정**: 지친 / 따뜻함 / 가벼운 / 생각이 많은 / 차분함 (말한 내용의 단어로 판단)
5. **그림**: 감정·출퇴근(아침 해/저녁 해)·날씨(비, 눈)로 그린 SVG 일러스트. `.env`에 `DIARY_IMAGES=openai`를 넣으면 AI 그림을 뒤에서 만들어 바꿔 끼운다(비용 발생, 실서버 미검증).
6. 서버 → 앱: `diary.ready {diary_id, view_url}`. 앱이 `view_url`을 **QR로 화면에 띄우고**, 휴대폰으로 찍으면 `GET /diaries/{id}` 페이지(그림 + 글 + 들은 이야기 요약)가 열린다.
7. 링크의 긴 무작위 ID가 유일한 열쇠다(프로토타입). 휴대폰에서 열리려면 `PUBLIC_BASE_URL`을 휴대폰이 닿는 주소로 설정해야 한다.

## 8. 메시지 정리

### 앱 → 서버 (`user.action` / `user.utterance`)

| 보내는 것 | 효과 |
|---|---|
| `session.started` | 서버가 주제를 골라 방송 시작 |
| `user.action` `select_topic` + `topic_key` | 그 주제로 |
| `user.action` `skip_topic` | 미리 만들어 둔 다음 주제로 (공백 없음) |
| `user.action` `random_topic` | 안 들어 본 분야에서 |
| `user.action` `next_segment` | 다음 문단 |
| `user.action` `set_interests` + `categories` | 관심 분야 저장 |
| `user.action` `request_story` | 사연 받기 시작 (직전에 사연을 들었으면 맞사연) |
| `user.action` `drop_music` + `track` | 음표 남기기 |
| `user.action` `play_relay` | 사연 릴레이 방송 |
| `user.action` `now_playing` + `track` | 지금 차에서 나오는 곡 ("이 노래 드랍해줘"용) |
| `user.action` `set_memory_consent` + `enabled` | 개인 메모리(회고) 저장 동의 |
| `session.started` + `topic_key`(선택) | 그 주제로 방송 시작 (데모, 출발 전 화면에서 고른 주제) |
| `user.utterance` (`is_final: true`) | DJ 대화 / 사연 / 음표 (`intent`: `CREATE_STORY`, `DROP_MUSIC` 선택) |
| `vehicle.parked` | (주차 확인 상태에서) Q Diary |

### 서버 → 앱 (계약 `broadcast-command.schema.json` 그대로, 새 필드 없음)

| 명령 | 앱이 할 일 |
|---|---|
| `dj.speak` | TTS 재생 → ACK |
| `story.preview` | 주차 후 승인 창 → `/approval` 호출 → ACK |
| `story.incoming` | TTS 재생 → ACK (다른 운전자 사연) |
| `media.pause` / `media.resume` | 재생 멈춤 / 재개 |
| `diary.ready` | `view_url`을 QR로 표시 |
| `music.play` | `url` 음원 재생 → 끝나면 ACK (계약에 새로 추가, 앱에 구현됨) |

### 차량 화면용 조회 API (읽기 전용, Bearer 토큰)

| API | 내용 |
|---|---|
| `GET /api/v1/sessions/{id}/now` | 지금 방송 중인 질문·분야·진행(문단 몇 번째/전체, 역할)·출퇴근·현재 곡 |
| `GET /api/v1/topics` | "주제" 시트에 띄울 주제 목록(분야별) |

앱 화면은 브라우저 데모(`backend/roadpod/static/demo.html`)와 같은 디자인을 앱 안 HTML(`app/src/main/assets/headunit/index.html`)로 옮긴 것이다. 앱이 WebView로 띄우고 `HU.update(state)`로 상태를 넘기며, 화면 버튼은 `Android.action(name)`으로 앱에 돌아온다.

서버가 보내는 모든 명령이 계약 스키마를 통과하는지 테스트로 확인한다(`test_every_new_command_matches_the_shared_contract`). `music.play`는 이번에 계약 스키마에 추가했다(다른 명령은 그대로).

- **배포 전 필수**: 사용자 인증(지금은 고정 토큰), 일기 링크 보호, 사연 검수를 사람 검토나 전문 모더레이션 API로, 개인정보 탐지 고도화(이름·주소는 AI 정리에만 의존).
- 세션 상태는 서버 메모리에 있어 서버를 재시작하면 진행 중인 방송이 끊긴다(DB 내용은 남음).
- 맞사연 관계 분류는 키워드 기반이다.
- 새 주제 후보는 자동으로 카탈로그에 들어가지 않는다(운영자 검토).
- 마이크 드롭은 곡 소개만 한다(재생·음원 연동 없음).
- AI 그림(`DIARY_IMAGES=openai`)은 실제 호출로 검증하지 않았다.
- 대화 답변이 가끔 주제에서 벗어나는 현상이 한 번 관찰됐다(원인 미확인).
- 음악 코너는 샘플 슬롯뿐이다(실제 무료 음원 파일을 골라 넣어야 소리가 남). 앱은 `music.play` 재생을 아직 구현하지 않았다.
- 출퇴근 프로필에 맞춘 실제 인기곡 편성은 음원 서비스 제휴가 필요하다(향후 과제).
- 회고 답은 그 회차 주제의 선호 신호로만 쓰인다(더 정교한 추천 반영은 미구현).

## 13. 데모 실행 — 시나리오 A(출근길)·B(퇴근길)

차 앱 대신 스크립트가 차 역할을 한다(차량 데이터 보내기, DJ 말 재생·ACK, 하은의 말 보내기). 서버 엔진은 실제 코드 그대로이고, 시계만 시나리오 시간(07:30, 19:10 …)으로 맞춘다.

```bash
cd server
.venv/bin/python demo/run_demo.py              # .env 설정대로 (OpenAI 키가 있으면 실제 AI)
.venv/bin/python demo/run_demo.py --pace 1     # 발표용: 한 줄씩 천천히
.venv/bin/python demo/run_demo.py --only B     # 퇴근길만
.venv/bin/python demo/run_demo.py --mock       # AI 없이 즉시 (고정 문구)
.venv/bin/python demo/run_demo.py --sound 8    # 음악 코너 음원을 8초씩 실제 재생 (음원 파일을 넣었을 때, 맥)
```

- 처음 실제 AI로 돌리면 주제 3개를 리서치·작성하느라 1~2분 걸린다. 결과는 `demo/episode_cache.sqlite`에 남아 **두 번째부터는 바로 시작**한다.
- 사연·음표·일기는 매번 새로 만든다(`demo/demo_run.sqlite`). 실제 서버 DB(`roadpod.sqlite`)는 건드리지 않는다.
- 끝나면 Q Diary가 `demo/output/A_출근길_Q Diary.html`, `B_퇴근길_Q Diary.html`로 저장되고, 맥에서는 퇴근길 일기가 브라우저로 열린다.

| 시나리오 장면 | 데모에서 보이는 것 |
|---|---|
| A 07:30 출근 프로필로 오프닝 | 출근 인사 + "무례한 사람을 꼭 내 편으로 만들어야 할까?" (밝은 목소리) |
| A 07:40 딥다이브 | 리서치 원고 (연구·기사 출처를 말로 밝힘) |
| A 07:55 사연 코너 | "팀장님 말투…" 사연 + 답장 + "라디오가 조금 더 따뜻해지네요" |
| A 08:05 신월 IC | 내비 안내 → 일시정지 → 재개, 끊긴 문장부터 다시 |
| A 08:15 올림픽대로 정체+비 | "올림픽대로가 비 때문에 조금 느려요. 도착은 12분쯤 늦어질 것 같아요." |
| A 08:45 신호 대기 중 사연 | 공감 + 초안 낭독 + "보낼까요?" → "응 보내" → "큐큐~" |
| A 08:50 주차 | 클로징 멘트 + Q Diary(오늘의 한 줄, 큐큐's 코멘트, 그림) + QR 주소 |
| A 주차 이후 | 사연 → 토픽 후보 → 승인 → **다음 날 다른 청취자의 오프닝 질문** |
| B 19:10 퇴근 오프닝 | 차분한 인사 + "나는 왜 퇴근하고도 회사 생각을 멈추지 못할까?" |
| B 19:15 아침 사연 답장 | "아침에 남겨 주신 사연에 답장이 왔어요…" "다른 분은…" |
| B 19:25 딥다이브 + 책 한 권 | 리서치가 확인한 책 소개 (실제 실행에서 마크 크로플리 『The Off Switch』) |
| B 19:50 퇴근길 사연 코너 | "오늘 처음으로 회의에서 내 의견을 끝까지 말했어요" + 답장 |
| B 20:00 마이크 드롭 | "이 노래 드랍해줘" → 「밤편지 - 아이유」 음표 저장 |
| B 20:15 회고 질문 | 정체로 멈췄을 때만 "오늘 하루에서 한 장면만 고른다면요?" |
| B 20:30 주차 | 클로징 + Q Diary(아침 사연, 돌아온 답장, 회고 한 줄, 음표) |
| B 이후 | 같은 구간 정체를 지나는 다른 운전자에게 「밤편지」 음표 소개 |

**시나리오와 다른 점**: 멘트는 시나리오 원고를 그대로 읽지 않고 엔진이 만든다(AI라 실행마다 조금씩 다름). 첫 주제가 끝나면 다음 주제로 자동으로 넘어가므로 08:05 이후는 두 번째 주제 위에서 진행된다. 음악 코너는 `♪ 음악` 줄로 표시되고, 음원 파일을 넣고 `--sound`를 주면 실제로 소리가 난다. 20:00 마이크 드롭의 「밤편지」는 차에서 듣던 곡(A) 역할이다. 하은의 프로필·다른 청취자 사연은 스크립트가 미리 넣는다.
